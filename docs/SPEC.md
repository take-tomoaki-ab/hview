# hview — Claude Code のレスポンスを HTML でライブ表示する仕組み

Claude Code とのやりとりで、AI の回答を「図つき HTML」として受け取り、ブラウザで常時表示しながら対話を続けるためのローカルツールです。

図つきの全体像は `docs/plan.html` にあります（ブラウザで開いてください）。本ファイルはその実装向けの要約です。

## 解きたい課題

ターミナル上の Markdown では、比較・フロー・レイアウトといった構造を持つ情報が読み取りにくいです。既存の `~/.claude/skills/html` スキルは単発の書き出しで、対話のたびに手で叩き直す必要があります。会話を続けている間ずっと「最新の図が横に出ている」状態を作ります。

## 方式

CLI + ローカルビューアです。Chrome 拡張・VS Code 拡張・デスクトップアプリは採用しません。理由は次のとおりです。

- Claude Code のどのフロント（ターミナル / VS Code / デスクトップ）からでも同じビューアに反映できる
- パッケージングや配布の手間がない
- 既存 `/html` スキルのテンプレートと作図ルールをそのまま流用できる

## 全体の流れ

```text
プロンプト（#html マーク）
  → UserPromptSubmit hook が「HTML で返せ」の指示を注入
  → Claude Code が .claude/hview/<session-id>/turn-<n>.html を Write
  → PostToolUse hook が hview server に通知
  → server が WebSocket でブラウザに push
  → ビューアが自動更新
```

## 構成要素

### 1. `hview` CLI（Bun + TypeScript）

- `hview serve [--port 5757]` … HTTP + WebSocket サーバを起動する
- `hview open` … ビューアをブラウザで開く
- `hview install-hooks` … Claude Code の設定に hook を登録する
- 外部依存は最小にする。フレームワークは使わない

### 2. 状態ファイル

```text
<project>/.claude/hview/
├── mode.json                 # ON/OFF と出力モード（毎ターン新規 / 同一ファイル更新）
├── server.json               # 起動中の port と pid
└── <session-id>/
    ├── index.json            # ターン一覧（タイトル・時刻・ファイル名）
    ├── turn-001.html
    └── turn-002.html

~/.claude/hview/              # プロジェクト横断。HTML は置かない
├── servers.json              # 起動中サーバのレジストリ（port / pid / projectRoot）
└── projects.json             # ビューアが扱ったプロジェクトの一覧
```

hook は `install-hooks --user` で全プロジェクトに入る一方、`hview serve` はどこか 1 プロジェクトで
起動する。この非対称を埋めるのが `~/.claude/hview/` の 2 ファイルで、次の 2 つを成立させる。

- **通知の宛先が分かる** … 通知元プロジェクトに `server.json` が無くても、レジストリから起動中サーバの
  port を引ける（既定値へのフォールバックだけだと、`--port` を変えていた場合に無音で落ちる）
- **サーバが複数プロジェクトを面倒見る** … `/api/notify` は projectRoot を運び、サーバは projectRoot ごとに
  状態を持つ。受け取った projectRoot は絶対パスかつ `.claude/hview` が実在することを検証し、
  URL には projectRoot ではなくハッシュ（`projectId`）を載せてパストラバーサルを塞ぐ

### 3. トリガー（3 系統）

いずれも最終的に `mode.json` の状態に集約し、判定ロジックは 1 箇所にまとめます。

| 系統 | 操作 | 有効範囲 |
| --- | --- | --- |
| インラインマーク | プロンプト内に `#html` と書く | そのターンのみ |
| スキルトグル | `/hview on` / `/hview off` | 解除するまで継続 |
| ビューアのボタン | ブラウザ画面右上のトグル | 解除するまで継続 |

### 4. hook

- `UserPromptSubmit` … モードが ON のとき、追加コンテキストとして指示文を注入する
- `PostToolUse`（`Write` matcher）… 対象ディレクトリへの書き込みを検知して `POST /notify` する。
  body には projectRoot を載せる。サーバが未起動なら無音で終わるが、**応答したうえで断られた場合は
  stderr に理由を出す**（HTML は書けているのに出ない状態を無音にすると、ユーザーからは
  「書き出されなかった」ようにしか見えない）

注入する指示の要旨は次のとおりです。

- 回答の実体は単一ファイルの HTML として `.claude/hview/<session-id>/turn-<n>.html` に Write すること
- チャット本文には 2〜3 行の要約とファイル名だけを書き、**HTML の中身を本文に貼らない**こと
- 比較・フロー・前後差分はインライン SVG の図にすること。外部 CDN・外部フォント・外部画像を使わないこと
- ライト / ダーク両対応にすること。`~/.claude/skills/html/assets/template.html` を土台にして見た目を揃えること

### 5. ビューア画面（ブラウザ 1 タブ）

左にターン履歴、中央にプレビュー、上部に操作系を置きます。

- 自動更新 … WebSocket 通知で差し替える。スクロール位置は維持する
- ターン履歴 … 過去のターンの図に戻れる
- ピン留め … 特定の HTML を固定し、どのセッションの新しいターンが来ても切り替わらない（**「見ながら対話する」の要**）
- 出力モード切替 … 毎ターン新規 / 同一ファイル更新
- 複数セッション … 同じプロジェクトで複数の Claude セッションが動くことを想定する。
  既定は「選択中のセッションを勝手に切り替えず、他セッションのターンは未読マーカーと通知で知らせる」。
  セレクタの「最新を自動で追う」を選べば追従に切り替わる。モード（`mode.json`）はプロジェクトに 1 つで共有する
- 複数プロジェクト … 1 つのビューアで複数プロジェクトのターンを扱う。セッションセレクタを
  プロジェクトごとの `optgroup` で束ね、上部にプロジェクト名を出す。モードの操作は
  **選択中セッションのプロジェクト**に向ける
- セキュリティ … プレビューは `sandbox="allow-scripts"`（`allow-same-origin` は付けない）の iframe に隔離し、CSP で外部通信を止める

### 6. エクスポート

生成物が単一ファイル完結なので、置き場所を選ぶだけで済みます。

- HTML をそのままダウンロード
- `~/Desktop/codes/html-output` へ保存（既存 `/html` スキルの出力先と揃える）
- 絶対パスをクリップボードへコピー
- ブラウザの印刷ダイアログ経由で PDF 化

## 実装フェーズ

1. **Phase 0 — PoC** … `hview serve` でファイルを配信し、ブラウザで手動リロードして表示できるところまで。hook はまだ繋がない
2. **Phase 1 — MVP** … hook 連携、WebSocket による自動更新、HTML ダウンロードと Desktop 保存。ここまでで要件を満たす
3. **Phase 2 — 対話性の強化** … ターン履歴、ピン留め、ビューア上のトグルボタン、同一ファイル更新モード
4. **Phase 3 — 任意** … プレビュー内の要素を選んで指示を送り返す逆方向フィードバック、VS Code Webview 版フロントエンド

Phase 2 までを今回の実装対象とします。Phase 3 は着手しません。

## 着手前に確認すること

設計の前提として置いているものの、裏を取っていない項目です。Phase 0 の前に実機で確認し、結果を `docs/findings.md` に記録してください。**前提が崩れた場合は自己判断で設計を変えず、確認できた事実と代替案を報告してください。**

| 項目 | 内容 |
| --- | --- |
| hook の入力仕様 | hook に渡される JSON からセッション識別子を取得できるか。取れない場合、ターンをどう束ねるか代替が要る |
| PostToolUse の matcher | `Write` ツールの実行を捕捉して、対象パスをサーバに通知できるか |
| 指示注入の効き目 | 「HTML の中身を本文に貼るな」がどの程度守られるか |
| iframe の制約 | `allow-same-origin` なしの sandbox で、図の中の JavaScript がどこまで動くか |
| port の選定 | 既定 `5757` が空いているか。起動時の生存確認と `--port` 指定を用意する |

## やらないこと

- 既存 `~/.claude/skills/html` スキルの変更・削除。単発書き出しは従来どおり `/html`、常時表示は `hview` という住み分けにする
- ユーザーの `~/.claude/settings.json` の**無断書き換え**。`hview install-hooks` は必ず差分を提示して確認を取る実装にする
- 外部 CDN・外部フォント・外部画像への依存
